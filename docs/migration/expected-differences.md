# Expected replay differences

Each entry here is a difference between the legacy app and the new app that we **intend**. A replay mismatch matching an
entry is reported as intended. Any other mismatch is a regression. Entries use the security-finding numbers from
`inventory.md` §13 and `plan/DECISIONS.md` (S1–S9), `G` for gateway behaviour, `E` for EF6 → EF Core behaviour
(`ef6-to-efcore.md`), `L` for legacy bugs, `D` for the shared (expanded) schema, `R` for rendering, `C` for coexistence, `A` for
pages answered by the Angular front end, `F` for full-text search, `N` for notification delivery and `X` for routes retired with
the legacy app and `I` for sign-in after it (round 4).

Status values: **active** means traffic already shows the difference; **ready** means the new code exists and the
difference appears when the listed routes move; **pending** means it is not yet confirmed against a legacy recording.

Round 2 (`routes`) moves the first routes (waves 0–3, `src/modern/TicketDesk.Web/migration-registry.json`). The replay
summary (`ops/dev/replay-summary.py`) explains a mismatch only when **every** diff of the exchange matches a rule in
`docs/migration/replay-explanations.json` (route + diff kind/path), so an unrelated diff in the same exchange still counts
as unexplained. The new endpoints (`/api/**`, `/health/*`, `/openapi/v1.json`) have no legacy counterpart.

`Legacy` the legacy app. Language: the Angular pages are English only (the language menu changes the other pages). Ticket text:

## Identity (round 2b)

Behaviour of the new app's sign-in that differs from the legacy app without causing a replay difference:

- **Shared sign-in cookie** (rounds 2b–3; gone since round 4, see I1). `.AspNet.ApplicationCookie` keeps its name and attributes (path, HttpOnly, Secure on HTTPS,
  no SameSite; the expired cookie at sign-out has path only, like OWIN). Its value is now an ASP.NET Core ticket protected
  with the Data Protection key ring in `dbo.DataProtectionKeys` (application name `TicketDesk`), which the legacy app reads
  through Microsoft.Owin.Security.Interop (`ticketdesk:SharedCookieKeyRing=database`). Cookies issued before the switch
  (machine-key format) are not readable: users sign in once again.
- **LDAP fallback.** The legacy sign-in tried an LDAP bind when `SecuritySettings.DefaultLogonDomain` was set
  (System.DirectoryServices, Windows only). The new app does not (it logs a warning); Entra ID OIDC replaces it. The lab
  has no logon domain, so no exchange shows it.
- **Entra ID.** A second sign-in option on the sign-in page, shown only when `Authentication:EntraId:Enabled` (replays
  run with it off, so the page stays the legacy one). The first Entra sign-in links an `IdentityUsers` row by e-mail /
  user name or provisions one (no password, login provider `EntraId`, key = `oid`); app roles set the direct legacy role.
- **Search manager.** `admin/search-manager/remove-index` and `populate-index` (wave 5) stayed on the legacy app until
  round 3, which retired them with Lucene (L4: the new app answers 410).
- **Push settings save.** The legacy POST restarted its own AppDomain so its in-process delivery re-read the settings;
  the new app reads settings per request and cannot restart the legacy app, whose delivery sees the change at its next
  app-pool start. The page keeps the legacy text ("The server has been restarted...").
